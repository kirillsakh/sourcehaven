## Spec [U] items relevant to M0-M1

| Item (spec section) | Resolution |
|---|---|
| RLS with `SET LOCAL` and the async driver (§5) | Verified in tests. The owner is set per transaction with `set_config('app.owner_id', ..., true)`. The policy reads it through `NULLIF(current_setting(..., true), '')::uuid` because a reset custom setting reads back as an empty string on reused pooled connections; no owner means no rows (fail closed). `test_rls_blocks_even_without_application_filter` (`tests/integration/test_retrieval.py`) queries chunks with no owner, document or configuration predicate and finds only the caller's rows; `tests/integration/test_schema_and_rls.py` covers the policies and the owner-scoped keys directly. Conversely, `test_application_filters_isolate_without_rls` (`tests/integration/test_isolation.py`) runs the repository and retrieval queries as the BYPASSRLS role and shows the explicit owner predicates isolate on their own. |
| TEI `/info` fields (§6.4) | `TeiEmbedder` checks `model_id` and `model_sha` against the configured model and revision; readiness fails on a mismatch. |
| TEI on Apple Silicon (§8) | TEI `cpu-1.9` publishes only `linux/amd64`; the platform is pinned in Compose and runs under emulation on arm64. The development host is x86_64, so its numbers are native. M2 does not use emulated numbers for acceptance. |
| Next.js buffering SSE (§4) | Avoided by routing: Caddy sends `/api/*` straight to FastAPI. `scripts/smoke-dev.sh` checks a streamed answer through Caddy. Flush timing is not asserted (see deferred M3). |
| `stream_usage` flag in langchain-openai (§7) | Confirmed against the installed langchain-openai 1.8.3: `stream_usage=True` puts `usage_metadata` on the last chunk; the output limit constructor alias is `max_completion_tokens`. |
| Tokenizer for prompt budget (§7) | `o200k_base` through tiktoken for OpenAI models tiktoken does not know; the encoding is pre-populated in the image and warmed in a thread at startup. The fake provider uses a conservative character estimate. The documented fallback for an unloadable encoding is the same estimate. |
| Client disconnect and cancellation (§11) | Verified in a test that disconnects mid-stream: the turn is stored as `interrupted` through a shielded write. Verified in-process, not through a browser. |
| Fixture font redistribution terms (§13) | Moot: the fixtures use Helvetica, a standard PDF base font, so no font file is vendored or embedded. |
| Printed page labels (§5) | Not implemented; pages are shown by index only. |
| HNSW expression-index syntax (§6.4) | Not needed; retrieval uses exact scans. Revisit when per-owner corpora grow. |
| Turnstile validity, test keys, free-plan terms, CSP requirements (§9, §11) | Not touched; Turnstile is M3 and CSP/security headers are M6. |

## Deviations and controller rulings

Rulings R1-R6 and per-task rulings are recorded in
`.superpowers/sdd/2026-11-19-m0-m1-skeleton-and-vertical-slice/progress.md` (local, untracked).
Summary:

- R3: an untracked local `.env` made from `.env.example` with dev-only values (no OpenAI key) is allowed;
  the real OpenAI smoke runs only when the owner supplies a key. R6: the ~1.2 GB TEI model download was
  covered by the plan approval.
- Container fields are added when their types exist (verifier in T9, file store in T10, chat model in
  T15); T14's `ready_visitor` gained its conversation in T17; `web` was added in T19, not T18.
- Integration fixtures take database role passwords from the environment (default `devpassword`,
  the same as the dev stack) because roles are cluster-wide.
- TEI runs at 3 GiB with `--max-batch-tokens 2048`; `SOURCEHAVEN_EMBEDDING_MAX_INPUT_TOKENS` is 2048
  to match. Chunks are 400 tokens, so nothing is lost.
- Build backend pinned to `uv_build>=0.9.17,<0.10` with uv 0.9.17 in CI and the image, matching the
  owner's installed uv. Bump both together after an upgrade.
- Docker Engine 20.10 / Compose 2.10 compatibility was kept (no `start_interval`, no `compose watch`).
- Foreign keys and unique keys are owner-scoped composites so cross-owner references fail and
  existence cannot be probed (T4 review).
- API error bodies are top-level `{"code": ...}`; validation errors map to `invalid_request`.
- Unresolved insert races return 409 `turn_in_progress`; a repeated `client_request_id` returns 409
  `duplicate_request` instead of the spec's replay (M3). SQL parameters are hidden from logs.
- Interrupted and failed turns store their supplied passages with `cited=false` so deletion (M5) can
  find them; `GET` hides the sources of non-complete turns.
- Token counting is injected through the container as `count_prompt_tokens`.
- Dev stack sets `SOURCEHAVEN_HUMAN_VERIFICATION=disabled` and `TRUSTED_PROXY=*` in the dev overlay only;
  each service gets only its own credentials (api and worker never receive admin or BYPASSRLS URLs).
- The unit-test environment ignores a local `.env`.
- Any test expecting page-specific citations from `multipage_en.pdf` overrides `chunk_tokens=40,
  chunk_overlap=5` (the fixture is one chunk at default size).
- M1 has no turn-id route, so turns are read only through `GET /api/conversations/{id}`; the isolation
  suite therefore covers conversation, document and question endpoints.
- Task 20: the isolation suite adds checks beyond the plan: `GET /api/documents/{id}` for a foreign
  id, asking about foreign document ids from one's own conversation, byte-identical 404 bodies for
  foreign vs unknown ids, positive controls, and 401 across all session-protected routes.
- Explicit owner predicates (spec §5.1, first layer) were missing outside retrieval until the final
  fix wave; every repository and ingestion query now filters on the owner it is given, so this is no
  longer a divergence. The app also refuses to start as a superuser or `BYPASSRLS` role, and
  `migrate` resets the roles' privilege attributes.
- Duplicate detection covers every state: `UNIQUE (owner_id, content_sha256)` and
  `find_by_content_hash` return the existing document even when its ingestion failed, so re-uploading
  a failed PDF returns the failed document. Spec §6.1 dedupes only ready or in-progress documents.
  Deferred to M3 (re-queue a new version when the latest version failed).
- Ingestion leaves `heading` and the chunker/ingestion fingerprints null (M2 for `heading`, M3 for
  fingerprints).
- Scope narrowed to English only on 2026-11-20 (see spec decision register); multi-language fixtures,
  font and `detected_language` removed (migration 0002).

### Behavioural rulings

- Evidence threshold is inclusive: a candidate with similarity exactly at the threshold is kept (≥).
- The per-document cap applies to the candidates that remain after the threshold, and only when they
  come from more than one document.
- Any PDF that pypdf reports as `is_encrypted` is rejected as `encrypted`, even if it opens with an
  empty password.
- Citation labels are ordered numerically (S2 before S10).
- A repeated `client_request_id` returns 409 `duplicate_request` instead of the spec §11.2 replay; an
  accepted divergence until M3.
- Generation temperature is unset by default (omitted from the request). The first real-provider
  smoke test showed `gpt-6-luna` rejects the proposed 0.2 with HTTP 400; spec §7.3 is updated.

## Deferred items by target milestone

### M2 (measurement)

- Chunk `heading` during ingestion (stays null in M1).
- `env_ignore_empty` makes an intentionally empty `SOURCEHAVEN_EMBEDDING_QUERY_PREFIX` revert to the
  default `query: ` (re-targeted from unscheduled; matters once prefixes are benchmarked).

- Re-measure TEI memory (2.84 of 3 GiB after one embed) and throughput; consider `memswap_limit`;
  link `--max-batch-tokens` to the max-input-token setting; readiness does not yet compare them.
- TEI `auto_truncate` silently truncates inputs over 2048 tokens (moot at 400-token chunks).
- Similarity-bound assertion (0..1) may flake with a real embedder; no `ORDER BY` tie-break in retrieval.
- Tests do not pin the `current_version_id` join or the embedding-config predicate (needs a superseded
  version and a second configuration).

### M3 (robustness and limits)

- Re-upload of a document whose latest version failed: queue a new version instead of returning the
  failed document (spec §6.1 dedupes only ready or in-progress documents).
- Logging configuration: no JSON formatter yet (spec §12), so INFO logs from the app are dropped.
- Worker does not verify the TEI model and revision at startup; no worker heartbeat or Compose health
  check (spec §6.4, §12).
- Chunker and ingestion fingerprints on versions (null in M1).
- CI `e2e` job (spec §13.5).
- General request-body cap for non-upload JSON routes.
- Graceful shutdown timing (uvicorn `timeout_graceful_shutdown` 30 s and a Compose
  `stop_grace_period`), paired with the stuck-turn sweeper below.
- `ALTER DEFAULT PRIVILEGES ... REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC` (re-targeted from unscheduled).

- Turnstile and `remote_ip` from proxy headers; rate limits, admission, spending ledger (usage of
  failed turns is currently discarded).
- Idempotent replay of a repeated `client_request_id`; cancel endpoint; follow-up timeouts.
- Child-process parsing limits, parse thread timeout, lease renewal during parsing, graceful worker
  stop; `scanned_no_text`, `skipped_pages`, `session_page_limit`; visitor message during embedding retries.
- Recovery sweeper for turns stuck `generating` after a crash; tiktoken warm-up timeout; unclosed upstream
  stream on disconnect may be cut short.
- Re-ingestion: superseding previous versions and ingestion fingerprints.
- Universal error shape (Starlette 404/405 and unhandled 500 still differ); streaming flush timing
  through Caddy and a per-line arrival record for the real-provider run.
- TEI over-length 4xx and `HashEmbedder` defaults duplicating Settings; tei.py robustness to
  malformed `/info` and embed responses.
- `cli.main` falls through to the worker for an unmatched command; readiness logs a full traceback at
  WARNING per failing probe and opens two sessions per probe.
- The 10-minute retry backoff is unreachable with fewer than three attempts (plan formula); the
  duplicate-chunks test passes even without the delete step; retrieval caps and limit are not validated
  for values <= 0; S1 and S01 are both accepted as distinct supplied labels.
- Chunker: `_fit` calls the token counter quadratically on one separator-free run, cuts back only to a
  space (not a newline), and counts chunks three times.
- Starlette spooled temp files are not closed on a mid-multipart client disconnect (bounded by the cap).
- Lease reclaim ignores attempts at claim time (the worker fails the job after three), and the claim
  function does not return the attempt number.

### M7 (deployment)

- Production Compose: migrate builds full Settings; worker needs `OPENAI_API_KEY` only for validation;
  pin `TRUSTED_PROXY`; Caddy non-root; admin role must be superuser-equivalent; pin base images by
  digest; TEI memory headroom.
- Dockerfile: split the dependency layer from source, `--compile-bytecode`, `**/` dockerignore patterns,
  hash-verified `uv export`.
- Packaging: `check-package.sh` forbids any `uploads/` or `docs/` directory (it would also reject a future
  package directory of that name); the test-only `cryptography` dependency is capped below 49 (no macOS
  x86_64 wheels beyond 48).
- CI: actions pinned by SHA, repeated setup-uv blocks, pre-commit cache.
- Compose and dev stack: the base Caddy service has no Caddyfile; the streaming curl in the smoke script
  lacks `--connect-timeout`; `db` and `embeddings` run as image default users and there is no explicit
  internal network.
- Compose: `${VAR:?}` guards require `.env` for any compose command; `build: .` repeated on three
  services; dev overlay publishes db on loopback.

### Unscheduled (cleanup and test hygiene)

- Settings: numeric sanity validation (`chunk_overlap < chunk_tokens`, positive limits); production

- Unused `SessionRecord.owner_id`; no lifecycle tests for engine dispose, the TEI client or partial

- Schema: the missing lookup indexes moved to M5 and the default function privileges for PUBLIC to M3.
- Misc: dev group lacks lower bounds; `uv_build` auto-detection checked empirically; `-p no:langsmith_plugin`
